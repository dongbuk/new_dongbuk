# 동북 스쿨월드 — 2단계 연결 구현판

기존 학교 탐험에 WebSocket 멀티플레이를 추가했습니다. 학생 32명과 교사 1명이 같은 학교에서 이동하는 구조이며, 역할 배정·체포·감옥·구출·승패를 서버가 판정합니다.

## 실행

Node.js 22 이상에서 `npm ci` 후 터미널 두 개로 실행합니다.

```sh
npm run server
```

```sh
npm run dev
```

브라우저에서 Vite 주소를 열고 `학생으로 함께 접속`, 학생 번호, 닉네임을 선택합니다. 기본 서버 주소는 `ws://localhost:2567/school`입니다. 다른 브라우저나 기기에서는 서로 다른 번호를 사용합니다. 같은 탭의 새로고침과 일시적 연결 끊김은 토큰으로 번호와 위치를 복원합니다. 다른 기기는 번호를 빼앗을 수 없으며, 연결 종료 30초 후 번호가 해제됩니다.

교사 접속은 서버 실행 환경에 TEACHER_CODE를 설정해야 합니다. 설정하지 않으면 교사 접속이 차단됩니다. 교사 코드를 Git이나 프런트 환경 변수에 넣지 마세요. 교사로 입장한 뒤 술래잡기 준비 → 게임 시작을 누릅니다.

## 외부 배포

프런트 `npm run build` 결과인 dist 폴더는 정적 호스팅에 배포할 수 있습니다. 이 정적 배포만으로 멀티플레이 서버가 생기지는 않습니다.

서버는 **상시 실행 Node.js 서비스 한 개**에 전체 소스를 배포하고 `npm ci --omit=dev`, `npm run server`로 실행합니다. 서버 환경 변수:

- PORT: 서비스에서 제공한 포트 (기본 2567)
- ALLOWED_ORIGINS: 허용할 프런트의 정확한 origin, 쉼표 구분. 예: https://학교게임.example
- TEACHER_CODE: 교사 전용 비밀 코드

TLS/WSS와 WebSocket 프록시를 지원하는 호스트를 사용하고, 프런트에서 `wss://서버도메인/school`로 접속합니다. `VITE_GAME_SERVER_URL`을 빌드 시 지정하면 주소가 기본 입력됩니다. HTTPS 페이지에서는 ws:// 접속을 차단합니다. `/health`가 상태 점검 주소입니다.

**현재 외부 실시간 서버는 배포되지 않았습니다.** 인메모리 단일 학교이며 서버 재시작 시 접속 상태가 초기화됩니다. 여러 서버 인스턴스로 확장하면 학교 상태가 나뉘므로 한 인스턴스로 운영해야 합니다. 공개 교실 배포 전 초대/방 격리와 실제 기기 부하 점검이 필요합니다.

## 조작과 동기화

WASD/방향키 이동, Shift 달리기, Space 점프, 드래그 카메라, E 벤치. 태블릿 조이스틱과 행동 버튼 유지.

서버가 30Hz 고정 이동과 충돌을 계산하고 15Hz로 상태를 공유합니다. 클라이언트는 즉시 이동을 예측하고 확인된 입력 이후를 재적용합니다. 다른 캐릭터는 위치 보간하며 번호/닉네임/동물 종류/연결 상태가 표시됩니다. 동물은 입장 전과 입장 후 자유 탐험·참가 대기 중 변경할 수 있습니다. 감정 표현과 벤치 자세는 현재 로컬 표현이며 다른 화면에는 전달하지 않습니다.

## 검증

`npm test` / `npm run build`

게임 규칙 및 33개 실제 WebSocket 연결 통합 테스트, 기존 동물/충돌 회귀 테스트를 포함합니다. 최신 실행 결과는 GAME_IMPLEMENTATION.md를 확인하세요.

로컬 33소켓 접속은 33대 기기 성능 보장이 아닙니다. 실제 브라우저 간 이동, 크롬북/태블릿 FPS, 인터넷 지연 및 장시간 부하는 아직 검증하지 않았습니다. 검증 브라우저에서 WebGL 지원이 제한되면 안내 화면이 표시됩니다.
